# Frotand-SA01

Situação de Aprendizagem 1 - Somativa - JavaScript

Tema: Desenvolvimento de Pequenos Projetos Interativos em Front End
Objetivo: Praticar conceitos de HTML, CSS e JavaScript ao criar projetos interativos e visualmente atrativos, desenvolvendo habilidades em Front End.

Objetivo do Projeto:
Neste projeto, os alunos terão a oportunidade de aplicar os conhecimentos adquiridos em HTML, CSS e JavaScript, criando projetos que envolvem interatividade com o usuário. Os projetos serão escolhidos de acordo com diferentes níveis de dificuldade (fácil, médio e difícil) para que todos possam aprender e desafiar suas habilidades.

Projetos Disponíveis:
Em trios, os alunos deverão escolher um projeto de cada nível de dificuldade (Fácil, Médio e Difícil). Aqui estão as opções:

Nível Fácil:
Piano Simples
Funcionalidade: Criar um piano com teclas interativas.
Os alunos criarão um piano simples onde o usuário pode clicar nas teclas para ouvir sons, utilizando HTML, CSS e JavaScript.

Nível Médio:
Semáforo
Funcionalidade: Criar um semáforo que muda entre as cores vermelha, amarela e verde com intervalos de tempo.
O projeto visa simular um semáforo, utilizando lógica de tempo e interatividade com a interface.

Cronômetro
Funcionalidade: Contagem regressiva ou contagem normal de tempo.
O projeto permite que o usuário inicie, pause, reinicie e visualize o tempo decorrido de forma clara.

Temporizador
Funcionalidade: Definir tempo para contagem regressiva.
Similar ao cronômetro, mas com a adição de definir um tempo específico para contagem.

Nível Difícil:
Pedra/Papel/Tesoura
Funcionalidade: Jogo interativo com a escolha entre pedra, papel ou tesoura, onde o computador também escolhe uma opção.
O projeto permite interações do usuário, comparando as escolhas entre o jogador e o computador, e mostrando o vencedor.

Jogo da Velha
Funcionalidade: Jogo interativo entre dois jogadores.
O projeto cria o famoso jogo de "Jogo da Velha", permitindo que dois jogadores interajam no mesmo computador.

Calculadora Simples Gráfica
Funcionalidade: Realizar operações matemáticas básicas (soma, subtração, multiplicação e divisão) com uma interface gráfica.
A calculadora deve ser simples de usar, permitindo a entrada e visualização dos resultados de cálculos.

Critérios de Avaliação:
Críticos:
Funcionalidade
O projeto deve cumprir seu propósito principal e funcionar corretamente. O código deve garantir que todas as funcionalidades propostas sejam executadas sem erros.

Interface de Usuário (UI)
A interface deve ser intuitiva, agradável e fácil de navegar. A estética visual deve facilitar a interação do usuário com o projeto.

Interatividade
O projeto precisa responder adequadamente às ações do usuário. Cada interação, como clicar ou digitar, deve gerar uma resposta visual ou funcional.

Responsividade
A interface deve funcionar bem em diferentes dispositivos, como desktops, tablets e smartphones, adaptando-se aos diferentes tamanhos de tela.

Qualidade do Código
O código deve ser limpo, bem organizado e documentado. Deve seguir as melhores práticas de programação, como o uso de variáveis e funções claras, sem repetições desnecessárias.

Desejáveis:
Estilo e Design
O design visual do projeto deve ser criativo e usar de forma eficaz cores, fontes e layout. Um design bem trabalhado melhora a experiência do usuário.

Comentários no Código
O código deve incluir comentários explicativos sobre as partes mais complexas, facilitando a compreensão e manutenção do código.

Performance
O projeto deve ser otimizado para um bom desempenho, sem atrasos ou lentidão, garantindo um carregamento rápido e suave.

Extras
Caso o projeto tenha funcionalidades extras que não são obrigatórias, isso será considerado um ponto positivo. Isso pode incluir animações, efeitos de transição ou funcionalidades adicionais.

Compatibilidade
O projeto deve ser testado em diferentes navegadores e garantir que funcione de forma consistente em todos.

Entregáveis:
Cada equipe deve entregar os seguintes itens:

Código-fonte completo
O código deve incluir os arquivos HTML, CSS e JavaScript utilizados no projeto.

Arquivos de mídia
Caso o projeto envolva imagens, sons ou outros recursos multimídia, todos os arquivos utilizados devem ser entregues.

Documentação (README.md)
Um breve documento explicativo sobre as funcionalidades do projeto, como ele foi desenvolvido, os desafios enfrentados e soluções encontradas durante o processo.

Cronograma:
Semana 1:
Introdução ao projeto: Explicação sobre os requisitos e etapas do projeto.

Escolha dos projetos: As equipes escolhem seus projetos (Fácil, Médio e Difícil).

Organização das equipes: Formação dos grupos de três pessoas e distribuição das tarefas.

Desenvolvimento dos projetos: As equipes começam a codificar os projetos.

Semana 2:
Testes finais e resolução de bugs: Verificação de erros e ajustes necessários para garantir que o projeto funcione corretamente.

Otimizações: Melhorias no desempenho e no design da interface.

Apresentações: Cada equipe apresenta seu projeto para a turma, explicando as soluções adotadas, desafios enfrentados e aprendizado.

Avaliação:
A avaliação será baseada nos critérios críticos e desejáveis listados acima. Cada projeto será avaliado individualmente de acordo com a complexidade escolhida pela equipe. Além disso, a participação ativa e o trabalho em equipe serão considerados na avaliação final. A capacidade da equipe de explicar e defender suas escolhas de design e implementação será um fator importante na nota final.
